# 动画编辑器走查清单

按「一个没上过手的人，从素材到引擎」这条真实路径走一遍，记录每一步的卡点。
路径：拆分件/选素材 → 新建工程 → 加轨道 → 建骨绑轨 → 变形/蒙皮/权重 →
导出 ZIP → 导出 Godot 包 → 在 Godot 里播放。

状态说明：**已修** = 本轮改掉了；**已知** = 记录在案、暂不改；**待做** = 建议但没排期。

---

## 1. 选素材与拆部件

- 素材库已有拆分表（四方向、9 宫格部件等）产出的图，动画编辑器可直接取用。
- **数据缺陷（本轮修）**：拆分产物的 meta 原来只有 `{pipeline, index}`，
  没有「这批图属于同一次拆分」的标记——库里 172 张拆分件在下游看是 172 张散图，
  任何「按组导入」的功能都无从谈起。
  → **已修**：每次拆分生成 `groupId`，并把格子位置 `cell`、网格 `grid`、
  可选 `sourceId` 写进 meta；新增 `GET /api/sprite/groups` 按组聚合。
- **角色部件拆分（本轮新增）**：之前只有「按格子切表」，头/身/四肢的语义没人给。
  方案是**人涂语义、机器做裁切**：后处理页新增「角色部件拆分」卡片，
  在角色图上直接涂（每部位一个纯色），服务端按颜色容差裁出 RGBA 部件，
  并做 de-fringe（用邻近颜色补透明区，避免半透明边缘显出与内容无关的色边）。
  没涂到的部位不生成图，结果里会点名。
  → **已修**：涂色搬进了编辑器（见下），后处理页保留为「批量出部件」入口。
- **本轮新增：编辑器里「涂部位 → 直接生成轨道与骨骼」**
  之前要在后处理页涂色、再切到动画页导入、再手动摆轨道——跨页来回一次，
  人就懒得用。现在编辑器左栏「涂部位建骨架」开一个浮层：
  选角色图 → 涂部位 → 生成，服务端同时返回「部件 + 骨架方案」，
  一次写入轨道与骨骼。
  - 部件会**裁到自身包围盒**（不裁的话每个部件都是整幅画布大小，
    pivot 落在画布底部、部件悬在半空）；
  - 骨架方案由服务端算（`parts.plan_rig`）：pivot 按部位取
    头/躯干下中点（绕脖子/胯）、四肢与尾巴上中点（绕肩/胯），
    面积最大的当躯干、其余挂躯干下，整体按并集包围盒缩放居中；
  - 涂色有**画笔/框选**两种：框选拖个矩形整块填色——描边容易漏，
    漏掉的像素切不出来，部件就会缺一块；
  - 部件间**实心像素互不重叠**（框选难免重叠，分配规则是「归给颜色最近的
    那个部位」），否则两个部件抢同一块区域，旋转时互相撕；
  - **分节链**：部位名带数字的（尾巴1/尾巴2/尾巴3）会串成父子链，
    转第一节后面几节跟着摆，才有波浪感。刻意不做「按几何猜链」——
    那会把「左上臂/右上臂」误串成一条（核心词都是「臂」），
    而它们本该是两条独立肢体。数字是用户明确表达的意图；
  - 层级推断完还能**手动改父骨骼**（右侧属性面板），改时挡住成环
    （挂到自己的后代上会让 FK 无限递归）。服务端也独立挡一道。
- **本轮新增：自动识别模式（默认）**
  之前涂色必须先从预设里选名字（头/身体/左上臂…），等于把「这是什么部位」
  的判断推给用户。其实用户涂色时看到的是「一个绿色的块」，
  正确顺序是**先涂，机器再告诉他这是啥**。
  - 默认给 8 块纯色（色1~色8），涂完由服务端按几何判断角色：
    躯干（跨越图形竖直中线、面积最大）→ 头（躯干上方）→
    尾巴（横向伸出）→ 臂/腿（躯干两侧，按竖直中心分）。
  - **旋转点也按几何定**：关节在部件哪一端（头在下=脖子、臂在上=肩、
    尾巴在靠身体那端）。这比按名字猜可靠——名字可能错，几何不会。
    用户**显式命名**的部件仍按名字走（他可能故意叫「上臂」而画的是朝上的）。
  - 识别结果显示在面板上，认错了可改名。
  - 「自己起名」模式保留原来的预设色板（含尾巴分节）。
    刻意**不做「按几何猜链」**：会把「左上臂/右上臂」误串成一条。
- → **已修**：编辑器左栏「导入拆分件」——选一组即生成「每件一轨 + 每件一节骨骼」，
  轨道与骨骼同名因而自动绑定，沿画布中心自下而上排开。
  没有 groupId 的旧数据会显示为「无分组信息」的散图条目，如实标注而不假装能用。

## 2. 新建工程

- 原实现：画布只能选 256/384/512/768 的**正方形**预设。
- 卡点：素材常是 512×768 之类非正方形，出画布后要手动救。
  → **已修**：改为宽/高分别可填，预设按钮退化为快捷填。

## 3. 加轨道

- 原实现：pivot 默认取贴图**几何中心**。
- 卡点：动画里的锚点几乎总是「脚底/落地点」。按几何中心放，角色会悬在半空，
  新手第一反应是「怎么在画布中间找不到它」。
  → **已修**：默认改为**底部中心**，并在添加提示里说明。
- 卡点：素材大于画布时默默出画布。
  → **已修**：添加后提示「素材 WxH 超出画布 WxH」。

## 4. 建骨 / 绑轨

- 卡点：骨骼链只能一根根「+ 子骨骼」，每根都要拖位置——新工程搭一套骨架的
  仪式感强到容易劝退。
  → **已修**：「生成骨链」面板——节数 2–6、每节 30–140px、朝向（垂直/水平）、
  起点（画布底部 / 当前轨道 pivot），一键铺一条等距链并选中末节；
  另配「按名绑轨」：轨道名包含骨骼名（或反之）就自动绑定，绑不上会提示改名。
- 绑轨下拉、显隐、层序都在轨道列表里，够用。

## 5. 变形 / 蒙皮 / 权重

- 变形 3×3 控制点、可打关键帧；蒙皮自动权重；权重笔刷可手刷。
- 卡点：**手刷数据按顶点下标存**，网格密度一改就错位。
  → **已知**：面板里有提示 + 一键「清除全部手刷」；更彻底的做法是按
  (u,v) 浮点坐标存权重，代价是工程变大。
- 卡点：没有扭转骨骼，长躯干（四足尾巴）必须拆很多节骨骼。
  → **待做**：可选的 twist 参考轴（用第三根骨骼当参考线）。

## 6. 导出 ZIP（帧序列）

- `frames/` + `sheet.png` + `normals/` + `project.json`，导出帧不带 AI 角标。
- 走查中未发现阻塞问题。

## 7. 导出 Godot 包（**本轮最大问题在这**）

- 原实现里 `anim_player.gd` 用 `load()` 读贴图。
- **实测缺陷**：把导出包直接拖进 Godot 工程（用户最可能做的事），
  因为 PNG 没走过 import 流程，`load()` 全部失败 →
  `track_material` 拿到 null 直接报错中断，**动画静默少画一截**，
  只有 stderr 里有一行警告，肉眼几乎看不出来。
  （这个问题当初就是我在做像素级验证时踩到的，当时只当成「测试环境问题」修了流程，
  没意识到它就是用户路径。）
- → **已修**：`load_texture()` 先用 `Image.load()` 读原始文件（不依赖 import），
  失败再退回 `load()`；两条路都失败时 `push_error` 并记入 `missing_textures`，
  **不再让整段动画中断**。包 README 写清了「不 import 也能跑；导成 PCK 才需要 import」。
- → **已验证**：`godot_verify` 新增「刻意不 import 直接跑」一档，
  像素与后端一致（MAD 0.00–0.97）。

## 8. 在 Godot 里播放

- 视口背景必须透明（`Window.transparent_bg = true`），否则与导出的透明画布
  整体偏色。→ **已知**：已写进包 README 与验证脚本。
- 混合模式：normal / add / multiply 已映射到 `CanvasItemMaterial`。
  已知口径差异：Godot 的 ADD 会累加 alpha，后端保持目标 alpha，颜色一致、alpha 略高。
- 改动骨骼后要重新导出（导出是逐帧烘焙，不是运行时骨架）。

## 建议的下一步（按收益排序）

1. **从零自动生成骨链** + 一键「把轨道按部件名绑到对应骨骼」——
   缩短第一次上手的时间，比再加高级功能更值钱。
2. **扭转骨骼（twist）**：解决长躯干必须拆很多节的问题。
3. **权重按 (u,v) 存**：彻底消除「改网格密度要重刷」的限制。
4. 拆分件结果直接进编辑器（生成部件轨道骨架），省掉手工加轨道。
