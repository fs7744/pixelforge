## 零、一句话定位

PixelForge 像素工坊是一个**本地运行的像素游戏素材工作站**：用本地模型生成素材，
用确定性管线把素材规整成引擎能直接用的形式，再用一个动画编辑器做精修。

一句话拆解：
- **生成**：文生图 / 图生图 / 指令式编辑（本地双底座）
- **规整**：抠图、像素化、拼精灵表、分层、去水印、无缝延展（纯确定性，不碰模型）
- **编辑**：骨骼动画编辑器（2D FK + IK + 蒙皮 + 变形 + 特效笔刷）
- **交付**：导出引擎可直接用的包（Godot 骨架包 / 帧序列 ZIP / GIF / 精灵表）

规模：前端 8 个页面 + 2242 行的动画编辑器；后端 69 个 HTTP 端点 + 22 个图像管线模块
+ 11 个动画引擎模块；测试覆盖 138 + 405 + 28 + 41 条断言。

## 二、逐功能清单

### 2.1 生成类

| 功能 | 干什么 | 大致思路 |
|---|---|---|
| **文生图** | 提示词 → 图 | 本地 Z-Image-Turbo。画风词**拼在提示词开头**（该模型的编码器是因果结构，尾部 token 权重最弱）。落资产库**不烧 AI 角标** |
| **图生图** | 1–4 张参考图 → 新图 | Z-Image 是纯文生图、无参考图输入，所以**自动改走编辑底座**（Qwen-Image-Edit），meta 标 `autoRouted` |
| **提示词模板库** | 12 个模板 / 7 分类 | 动态下发，占位符填成可直接跑的默认值。`kind=text` 的模板只给操作指引，**不假装能做** |
| **美术画风库** | 15 种画风 + 分类推荐 | 风格词统一中文且置顶；每种带 `suggestPost` 像素化建议（HD-2D 是唯一不配像素化的） |
| **三视图** | 角色正/侧/背 + 拼板 | 正视图唯一需要文生图；侧/背由它用编辑底座推导（保一致性）。分步可单独重跑，重跑上游自动作废下游 |
| **逐帧动作生成** | 一次生成一帧 → 拼精灵表 | 逐帧生成而非一次出多帧——模型没有「第 N 格画什么」的定位能力。身份由同一张参考图钉住，**动作不会重复** |
| **人物像素化** | 照片 → 像素角色立绘 | 两段式：AI 按档位重绘造型（3 档：写实比例/半 Q 版/Q 版）+ 确定性像素化收尾。返回**两套资产**（成品 / AI 原稿），原稿可毫秒级重像素化不占 GPU |
| **AI 画风重统一** | 旧资产 → 目标画风 | 长边压 1024 编辑后 Lanczos 放回，**尺寸前后一致**便于叠对比滑块 |
| **AI 去水印 / AI 延展** | 无掩码的去水印 / 左右续画 | 去水印靠指令让模型按周围补全；延展用**均值色画布 + 纯正向指令**（否定约束会让模型原样保留边距） |

### 2.2 确定性后处理管线（14 条，不碰模型）

| 管线 | 干什么 | 大致思路 |
|---|---|---|
| **抠图** | 去背景 | u2net 深度抠 → GrabCut → 颜色键三级降级。连通域洪泛 + 有限梯度生长；**despill** 改写「仍接近底色」的轮廓像素为内部色，色相溢出单独处理 |
| **像素化** | 转像素风 | 分块降采样（box 区域平均，非最近邻，避免脏斑）→ 限定色板量化（**全局共享色板**，防逐帧偏色闪烁）→ 最近邻放大。内置 GameBoy / NES 固定色板 |
| **精灵表拆分** | 1 张表 → N 张帧 | 按行列拆，顺带逐帧抠图。产物带 `groupId` 供编辑器识别同套部件 |
| **精灵表合成** | N 帧 → 1 张表 + 索引 JSON | 透明像素 RGB 恒置 0（防引擎双线性采样出色晕/图集串色）。**交付前逐格自检**（与源帧逐位一致 + 空白区全透明） |
| **精灵帧规整** | 帧序列 → 尺寸统一 | 抠图 → 裁空白 → 最近邻缩放 → 底部居中。**共享缩放**（先量所有帧最大包围盒再统一缩放，否则下蹲帧各自撑满会让角色忽大忽小） |
| **循环段选择** | 取 [start, stop) 连续段 | 不插帧、不跳帧、不改时长 |
| **角色部件拆分** | 角色图 → N 个 RGBA 部件 | 用户涂部位色标 → 按颜色裁切 + **几何识别**（判定顺序：躯干→头→尾巴→臂/腿）+ 规划骨架方案 |
| **场景语义分层** | 1 张图 → N 张同坐标图层 | 拆**同一张**图而非各生成 N 遍，天然对齐无接缝。层序用「主体底边越低越近」的 2.5D 约定 |
| **参考图规范化** | 任意图 → 方形画布 + 底部基线 | 主体包围盒（有 alpha 用 alpha，无 alpha 用四角底色做颜色键），画布边长 16 对齐（编辑底座要求） |
| **尺寸规整** | 缩放到目标尺寸 | 最近邻硬缩放 / 等比留白 / RPGMaker 三档（144×144、144×240、144×192） |
| **无缝延展** | 1 张 → 左右/上下镜像延展 | 镜像模式接缝像素天然相同（不做淡化）；重复模式才做窄带高斯柔化 |
| **瓦片接缝修补** | 任意贴图 → 可平铺单元 | 偏移-修复法：`roll` 半宽半高 → 中央十字区高斯模糊 + 邻域插值 → roll 回。**保留图案结构**而非整体模糊 |
| **法线 / 材质掩码** | 逐帧几何法线 + 金属掩码 | 高度场 = 0.78×内缩距离 + 0.22×亮度；法线 = 高度场 Sobel 梯度转切空间向量（OpenGL 风格，DirectX 需翻绿通道） |
| **确定性去水印** | 去掉 AI 角标 | 反向 Alpha 混合 `original = (watermarked - a·logo) / (1 - a)`。**无掩码不破坏性处理**，meta 标 `applied=false` |
| **视频/GIF 拆帧** | 录像/GIF → 帧资产 | **魔数嗅探**识别媒体类型（不信 content_type 与扩展名）。GIF/WebP 走 PIL 原生，MP4 必须 ffmpeg |
| **帧审查图** | 一眼看帧稳不稳 | 所有帧排网格，标逐帧差异 + 循环接缝 + 卡住的帧 |

### 2.3 动画编辑器（项目最重的一块）

**核心能力**

| 能力 | 干什么 | 大致思路 |
|---|---|---|
| **多轨合成** | 正常/相加/正片叠底混合 | 逐轨关键帧（位移/旋转/缩放/透明度） |
| **2D FK 骨骼** | 父子级联骨骼 | 用 **3×3 仿射矩阵级联**（父子关系 = 矩阵相乘） |
| **IK** | 拖手柄摆姿势 | FABRIK 解算（链长 2–4）+ pole 向量防翻肘。IK 权重可逐帧打点（0=跟 FK，1=跟目标） |
| **骨骼蒙皮** | 网格跟随骨骼弯曲 | 自动权重（顶点到骨段距离，取最近两根归一化）+ 手刷覆盖。手刷权重按 **(u,v) 归一化坐标**存而非顶点下标 → **改网格密度不会错位** |
| **3×3 自由变形** | 双线性网格变形 | 9 控制点可打关键帧，吃贝塞尔曲线 |
| **特效笔刷** | 5 种程序化笔迹 | 矢量笔迹按折线生成多边形；**固定随机种子**，同笔迹任意尺寸重渲染逐字节一致 |
| **序列帧轨道** | 精灵表当一条轨道 | 按帧号取格。布局优先读资产 meta，读不到则**按内容段周期检测**格数 |
| **序列帧循环段** | 只播 [start, stop] | 替代「回工作流重跑一次循环段选择」 |
| **循环接缝诊断** | 接缝跳不跳、哪格跑飞 | 对着当前循环段算，口径与拼表阶段一致 |
| **插帧** | 关键帧补间 + 位图光流插帧 | 值按当前贝塞尔曲线求值（复用渲染同一份数学），曲线形状不变；位图插帧走双向光流而非交叉淡化 |
| **撤销/重做** | Ctrl+Z | 60 步栈，700ms 同 label 合并（一次拖动算一步） |
| **版本快照** | 服务端快照 | 保存前自动存旧版；恢复前先给现状存一份（可再退回来） |

**导出格式**

| 格式 | 内容 |
|---|---|
| Godot 骨架包 | `anim.json`（**逐帧烘焙**骨骼世界矩阵 + 蒙皮顶点）+ 纹理 + `anim_player.gd` 参考运行时 + README。运行时不做骨链/权重计算，避免两套数学漂移 |
| ZIP 帧序列 | `frames/*.png` + `sheet.png` + `project.json` +（可选）`normals/` |
| GIF | 自研编码器（全局调色板 + 全局透明索引 + LZW），避开 PIL 的两个坑 |
| 精灵表/四方向包 | `SpriteFrames` + `AnimatedSprite2D` + 索引 + SHA256SUMS 清单 |

### 2.4 工作流引擎

5 条多步链，支持单步重跑、产物自动传递、状态落盘：

| 工作流 | 步骤链 |
|---|---|
| 动画 | 三视图 → 动作帧生成 → 抽帧去重(dhash) → 插帧补帧 → 抠图规整 → 精灵表 → Godot 包 |
| 动画·视频生成 | 角色锚点图 → 视频生成动作(Wan2.2) → 抽帧去重 → 插帧 → 抠图规整 → 精灵表 → Godot 包 |
| 四方向行走 | 四方向立绘 → 每方向 4 帧循环 → Godot 四向包（含方向控制器脚本） |
| 视差 | 场景参考图 → 语义分层 → 同尺寸规整 → 无缝延展 → 视差工程导出 |
| 场景元素 | 场景参考图 → 元素批量提取 → 拼装预览 |

### 2.5 基础设施

| 模块 | 干什么 |
|---|---|
| 资产库 | 本地落盘 + `index.json` 元数据 + 进程内索引缓存（按 mtime 失效）+ sha256 溯源 + **kind × pipeline 双维标签** |
| 任务进度 | SSE 推送「第 x/y 步 + 已用时长」，可随时取消（下一步回调抛 `CancelledError` 中止推理） |

| 本地双底座 | Z-Image-Turbo（文生图）+ Qwen-Image-Edit-2511（指令编辑），家族互斥显存换出，fp8 量化落盘缓存 |

## 三、贯穿全局的设计原则（值得带走）

这几条是这个项目里最有价值的部分，新项目应该继承：

1. **「数学只有一处实现」**
   贝塞尔求值、蒙皮权重、Godot 骨骼矩阵全部后端单点实现并**被导出烘焙**，
   前端与引擎侧不复刻。预览与导出走同一套渲染代码 → 所见即所得。

2. **确定性优先，模型是可选的**
   22 个管线模块里只有 6 个碰模型，其余全是纯 PIL/numpy 算法。
   好处：不需要 GPU 就能跑全部后处理；测试不依赖模型（`smoke_test.py` 138 条断言
   全部无需模型）。

3. **失败要给出可行动的下一步**
   `metrics_verdict` / 体检报告 / 素材库筛选空态——数字和提示都要能翻译成
   「所以你现在该做什么」。

4. **生成侧的缺陷要在生成侧修**
   绿幕脏不是抠图参数的问题（实测模型画不出纯色底，还会把绿染进角色）。
   所以默认底色改中性灰，抠图走语义分割（根本不看背景色）。

5. **验证要独立于被验证对象**
   Godot 验证不只查「引擎是否忠实照做 anim.json」（两边一起错时查不出来），
   还要查「导出数据 == 后端渲染实际用的东西」。用注入错误确认检查本身有效。

## 四、已知缺陷与边界

### 4.1 功能边界（设计上的取舍，不是 bug）

| 项 | 边界 |
|---|---|
| 骨骼 | 2D FK + 可选 IK。**没有约束系统**、没有扭转骨骼（twist）。四足长躯干要拆多节骨骼才不扭 |
| IK | 链长最多 4 节。**pole 是静态的**，不能逐帧变——同一个 IK 想在两个镜头换肘向得建两个目标 |
| 关键帧 | 逐轨 + 逐骨骼 + 逐 IK 目标。缓动支持命名档 + 自定义 cubic-bezier（y 允许出框做过冲回弹）。**没有曲线叠加**、没有循环修改器 |
| 3×3 变形 | 粗网格，做大变形会看出折痕 |
| 法线 | 不是 h3 的标注传播，是从像素反推（内缩距离 + 亮度）。**薄片、遮挡边界、正对镜头的平面会有偏差**，够做 2D 光照，不够做精确形体 |
| GIF | 256 色、1-bit 透明、逐帧栅格化。要保真用 ZIP 帧序列 |
| 手刷权重 | 按 (u,v) 存（已解决密度错位），但**没有拉链/自动平滑**，密集手刷边缘可能硬 |
| 特效笔迹 | **全帧可见**（笔迹带 from/to 区间但界面默认铺满整段） |
| 逐帧生成 | 一次一帧，慢。N 帧 = N 次推理 |
| 去水印 | 针对性算法，Google 改版即失效 |
| 确定性去水印 | 需要水印掩码图；**无掩码时不破坏性处理**（标 `applied=false`） |

### 4.2 真正的技术债

| 问题 | 影响 | 现状 |
|---|---|---|
| **前端单文件过大** | `Editor.tsx` 2242 行、`PostProcess.tsx` 1156 行、`Workbench.tsx` 1246 行。改动风险高、难以并行 | 未拆 |
| **无 UI 框架** | 37KB 单文件 CSS 手写全部视觉；无组件库、无状态管理库 | 组件只有 2 个（PartPainter / PartRigBuilder） |
| **绕过 api.ts 直接 fetch** | 5 处（unload / seamless/ai / restyle / watermark×2）散在 views 里，类型丢失、错误处理不统一 | 技术债 |
| **管线定义双份** | 14 条后处理管线在前端 `PIPELINES` 常量和后端 `workflows.py` 各写一遍，容易不同步 | 已知 |
| **测试环境** | `coverage_api_test.py` 里 Godot 那条**长期失败**（环境时序问题），单独跑 `godot_verify.py` 才通过 | 已知未修 |
| **workbench 模板数不一致** | README 写「10 个模板 × 6 分类」，后端实际 12 个模板 / 7 分类 | 文档滞后 |
| **Godot 验证需外部程序** | 依赖本机 `Godot_v4.3-stable_win64_console.exe`，CI 上跑不了 | 环境依赖 |
| **序列帧蒙皮权重共用** | 权重是整条轨道共用，没有「每格单独编辑」 | 功能缺口 |
| **循环段只能输数字** | 没有「在精灵表上框选一段」的交互 | 功能缺口 |

## 五、待完成功能清单

### 5.1 已明确写进文档的「下一步」

优先级从高到低（按当时的判断）：

1. **从零自动生成骨链** + 一键按部件名绑轨 —— 缩短第一次上手时间
2. **扭转骨骼（twist bone）** —— 解决长躯干必须拆多节的问题
3. **权重按 (u,v) 之外的手感优化** —— 拉链/平滑（(u,v) 存储已解决密度错位）
4. **拆分件结果直接进编辑器** —— 已部分实现（groupId 分组导入）
5. **序列帧的更多玩法**：
   - 每格单独编辑蒙皮权重
   - 循环段选择支持「在精灵表上框选」
   - 序列帧接缝检查（已实现，可扩展到 GIF/引擎侧）

### 5.2 缺失但没写进文档的

- **撤销栈只在前端**：服务端快照和前端撤销栈是两条独立的线，没有统一
- **多工程/工程模板**：只能新建空白工程，没有「从现有工程派生」
- **协作**：完全单机，没有工程导入导出（只有导出 ZIP/GIF/Godot，没有工程 JSON 的导入）
- **批处理**：素材库只能批量导出 ZIP，不能批量跑管线
- **管线编排**：14 条管线各自独立，没有「把 5 条串起来」的用户自定义链（后端 workflow 是写死的 5 条）
- **性能**：动画渲染纯 CPU 单帧几十毫秒，长工程（100+ 帧 × 多轨道）会卡
- **色彩管理**：全程 sRGB 假设，没有色彩空间转换

## 八、怎么把归档项目跑起来
