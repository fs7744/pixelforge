### 1.2 可复用的方法论（本项目直接吸收）

**① 两段式「规范文档防偷懒」提示词法**（0代码编程体系的核心）
- 第一段：让 AI 先产出一份《代码规范文档》（商业工程质量、操作体验优化、常见 bug 预判）
- 第二段：规范文档 + 详细需求 → 生成代码
- 启示：PixelForge 的提示词模板不应只是"生图描述"，而应是**多段式工作流**——每段有明确交付物，段与段之间以上一段产物为输入

**② 代码工程规范清单**（用于模板库的"编程"类模板）
- @export 导出所有参数、禁魔法数字；_physics_process 处理物理；类型安全；模块化拆分
- 手感优化：斜移 normalized、lerp/move_toward 平滑加减速、move_and_slide、微小速度归零
- 小白四原则：不让用户编辑代码 / 参数全在编辑器菜单 / 附中文配置说明 / AI 代配置节点

**③ 场景元素提取五诫**（HD-2D / 分层场景共用）
1. 每元素一张独立图 + 独立提示词（并行生图，禁用总括语句）
2. 遮挡区域完整补全，禁止悬空/截断
3. 统一纯色底（暗紫 #2A153F / 暗绿），便于后续抠图
4. 保持原图尺寸 + 原坐标（1672×941），导入引擎后初始位置一致
5. 建筑保持正视图不倾斜；地面平面化去透视

**④ 视差图层结构**（二维分层场景）
- 9 主图层 + 1 可选前景遮挡层，每层绑定 Godot `scroll_scale`（0~1.2）
- 关键洞察：**拆层 ≠ 无缝循环**；角色移动超出一屏宽度时，每层需单独制作左右无缝延展版本——这正好命中 PixelForge 的「像素网格对齐」管线

**⑤ 插帧法动画生产链**（角色生成，FrameRonin 完全没有的能力）
- 三视图（正/侧/背）→ 动作视频提示词（摄像机固定、角色原地、纯色底）→ 视频抽帧 → 两帧之间生成指定中间帧 → 精灵帧动画
- 中间帧提示词三要素：保持朝向/大小/细节不变、保持地面位置、**必须看到动作变化**（防 AI 输出近似帧偷懒）

**⑥ 瓦片接缝修补**：13×13 瓦片分析 → 风格迁移保持结构 → 接缝自然过渡 → 与 perfectPixel 网格对齐算法天然互补

**⑦ 多 agent 并行工作流模式**：一次启动 N 个子 agent，每个负责一组生图任务，完成后质检（正交视角/结构还原）→ PixelForge 的批量任务队列应对齐此模式

## 二、PixelForge 思路优化

### 2.1 定位升级

| | 原定位 | 优化后定位 |
|---|---|---|
| 产品 | 像素素材工作站（生成 + 后处理） | **AI 游戏素材与工程工作流平台**（素材 → 动画 → 场景 → 引擎工程） |
| 用户 | 像素美术使用者 | 独立开发者 / 小团队 / 无代码游戏创作者 |
| 终点 | 导出 PNG/GIF/精灵表 | **导出可直接进 Godot 的工程资产**（.tscn / 动画配置 / 视差参数） |

一句话：**从"素材工具"升级为"从提示词到可运行游戏工程的流水线"**。

### 2.2 功能矩阵：现状 vs 教程增强

| 模块 | 设计稿现状 | 教程增强点 | 优先级 |
|---|---|---|---|
| 提示词模板 | 4 个生图模板 + A0/A1/A2 关键字 | **模板库扩展为 6 大类 20+ 工作流模板**（见 2.3） | P0 |
| 角色生成 | 文/图生图 → 精灵表 | + 三视图一致性工作流 + 画风提取模板 | P0 |
| 动画生产 | 连生动作 V4Tx3（Gemini 外链思路） | **+ 插帧法工作流**（三视图→动作视频→抽帧→中间帧→精灵表） | P0 |
| 场景生成 | 无 | **+ HD-2D 场景工作流**（参考图→元素批量提取→场景拼装） | P1 |
| 视差场景 | 无 | **+ 二维分层视差工作流**（9+1 图层 + scroll_scale 编辑 + Godot 导出） | P1 |
| 瓦片贴图 | 无 | + 瓦片分析/风格迁移/接缝修补（复用网格对齐算法） | P1 |
| 后处理管线 | 7 条（去水印/抠图/RPGMaker/精灵表/网格对齐/视频抽帧） | + 智能抽帧（去重复帧）/ 图层同尺寸导出 / 序列帧补全 | P1 |
| 引擎对接 | 引擎 JSON（Godot） | **+ Godot 工程包导出**：.tscn 场景模版、AnimationPlayer 配置、scroll_scale 参数表、碰撞区自动匹配 | P0 |
| 编程辅助 | 无 | **+ 规范文档生成器**（两段式防偷懒法）+ 系统模板（移动/状态机/战斗/菜单） | P2 |
| 批量任务 | 任务队列卡（2 项） | + 多 agent 并行模式（一次 N 组任务 + 自动质检） | P1 |

## 三、项目方案

### 3.1 产品定位

**PixelForge（像素工坊）**——本地优先的 AI 游戏素材与工程工作流平台。

- **核心差异**：不卖"单张出图"，卖"从一句话到 Godot 工程资产的完整流水线"
- **技术底座**：站点自持 diffusers 推理引擎（本地模型），兼容 A1111/Forge 接入，云端 API 兜底
- **目标用户**：独立游戏开发者、无代码创作者、小团队美术外包

### 3.2 信息架构

```
PixelForge
├── 工作台首页（仪表盘：模型状态/最近资产/快捷工作流）
├── 生成工作台（模板库 + 参数 + 结果画布 + 导出）
│   └── 两种模式：单图模式 / 多段工作流模式
├── 动画工作流（三视图→视频→抽帧→插帧→精灵表）【新增】
├── 场景工作流（参考图→元素提取→拼装→Godot 导出）【新增】
├── 后处理工作台（10 条管线 + 前后对比 + 参数）
├── 素材库（资产网格 + 标签 + 详情 + 版本）
├── 模型设置（Provider 三形态 + 模型管理 + 默认值 + 系统）
└── 设计规范（ tokens + 组件库）
```

### 3.3 核心功能模块

**M1 提示词工作流引擎**（P0，产品灵魂）
- 模板 = 有序步骤序列，每步定义：输入（上一步产物/用户上传/参数）、提示词模板、校验规则
- 多段工作流状态机：可暂停、单步重跑、步骤间传递产物
- A0/A1/A2 关键字集机制（继承 FrameRonin 约定）

**M2 生成引擎层**（P0）
- Provider 抽象：内置 diffusers（默认）/ A1111 / 云端 API
- 模态路由：文生图 / 图生图 / 视频生成 / 插帧（frame-to-frame）
- 任务队列：支持批量并行（对齐教程的 N 子 agent 模式）+ 自动质检（尺寸/正交性/网格对齐度）

**M3 后处理管线**（P0，继承 FrameRonin 算法重写）
1. 反向 Alpha 混合去水印（Gemini/即梦）
2. 左上连通域抠图（容差/羽化）
3. RPGMaker 一键管线（144/192/240）
4. Sprite Sheet 拆分/合成/偏移重排
5. 完美像素网格对齐（FFT+Sobel）
6. 视频转序列帧 + 智能抽帧去重
7. 图层同尺寸同坐标导出（视差工作流专用）
8. 瓦片接缝修补
9. 左右无缝延展
10. GIF/引擎 JSON 导出

**M4 Godot 工程导出**（P0，教程体系的核心价值落点）
- .tscn 场景模版（暴露：贴图/缩放/九宫格中心点/镜像开关/碰撞自动匹配）
- AnimationPlayer 配置（帧率 0.1s、idle/run/attack 命名规范）
- 视差层 scroll_scale 参数表（9+1 层预设）
- 粒子参数暴露模版（10 参数）
- 碰撞区随缩放联动

**M5 规范文档生成器**（P2，差异化）
- 两段式：先规范文档后代码；内置防偷懒清单（@export/物理同步/类型安全/手感优化/bug 预判）
- 模板：角色移动/动画状态机/敌人 AI/战斗/迷宫切换/菜单道具

### 3.4 技术架构


### 3.5 实施路线图

**阶段 0：MVP 验证（2 周）**
- 静态前端 + FastAPI + 内置 diffusers（txt2img/img2img）
- 3 条核心管线：去水印 / 连通域抠图 / 尺寸规整
- 模板库 V1：10 个单图模板（角色/场景/瓦片）
- 目标：跑通"一句话 → 透明底像素素材"全链路

**阶段 1：工作流化（3 周）**
- 提示词工作流引擎（多段状态机 + 单步重跑）
- 动画工作流屏（三视图→视频→抽帧→插帧）
- 智能抽帧 + 智能去重
- Godot 导出 V1：.tscn 模版 + 精灵表 JSON

**阶段 2：场景与视差（3 周）**
- 场景工作流屏（元素批量提取 + 拼装画布）
- 视差 9+1 图层 + scroll_scale 编辑 + 无缝延展
- 瓦片三件套（分析/迁移/接缝修补）
- 多 agent 并行批量 + 自动质检

**阶段 3：工程化与合规（2 周）**
- 规范文档生成器 + 系统代码模板
- AI 内容标识全链路（显式 + 元数据）
- Docker 一键部署 + 用户文档

### 3.6 风险与对策

| 风险 | 对策 |
|---|---|
| 本地模型视频/插帧质量不稳定 | 插帧走"图生图低重绘"路线；视频模态作为可选项，不阻塞主链路 |
| 教程提示词依赖特定模型（image-2/gpt-image）行为 | 模板参数化（模型无关的描述结构），内置模型适配层做提示词微调 |
| Godot 版本差异（4.7） | .tscn 导出做版本探测，提供 4.x 兼容格式 |
| 帧间插画"近似帧偷懒" | 质检规则内置：中间帧与首尾帧差异度阈值检测，不达标自动重生成 |
| HD-2D 元素提取的遮挡补全不可控 | 提供"补全区域"手动涂抹兜底 + 质检提示 |

### 3.7 成功指标（MVP 后）

- 全链路耗时：一句话 → 透明底素材 < 3 分钟（本地 SD1.5 档）
- 工作流完成率：多段工作流单次通过率 > 70%
- 素材即用率：导出资产无需手工修正直接进 Godot 的比例 > 60%

## 四、结论

教程资源给 PixelForge 带来的最关键三样东西：
1. **两段式规范文档提示词法** → 升级为"提示词工作流引擎"的产品核心差异
2. **插帧法动画生产链 + 视差图层 + HD-2D 元素提取** → 三条 FrameRonin 完全没有的工作流，直接构成产品的功能护城河
3. **Godot 工程导出规范** → 把终点从"素材文件"改到"可运行工程"，用户价值倍增

下一步：按阶段 0 启动 MVP，或先在设计稿中补 S7/S8 两屏工作流界面。
